# AIC 知识变现 Stage 0（验证）设计

- 状态：Stage 0 立项
- 日期：2026-11-10
- 归属：AI辅助研发咨询顾问团队（AIC，公司 `66563a2a-3d6c-444c-90cb-e77ade723e96`）
- 上级项目：咨询指挥部 `8038e7dc-3c03-4dad-a61a-4013ddc55330`
- 决策：**先建变现项目，不建渠道子组织、不新增 Agent**

## 1. 结论与理由

知识变现的单元是**价值链**，不是渠道。公众号与小程序是同一价值链上的两个分发面：

内容生产 → 产品化/定价 → 分发（公众号/小程序）→ 支付履约 → 留存复购 → 数据迭代

按渠道拆子组织会重复内容运营、客服与数据，并把归因切碎；而"自己养活自己"必须由一个**单一 P&L 责任人**对"收入−成本"负责。因此：

- **现在**：一个变现专项跑通最小闭环。因 Paperclip 的 Agent 单项目绑定约束，Stage 0 以现有项目内的 issue 承载，不新建独立项目。
- **验证通过后**：升格为「知识变现」子组织（渠道仍是内部 runbook，不拆团队）。
- **单渠道规模化后**：才考虑按渠道拆团队。

平台风险（公众号审稿、小程序类目、支付资质、封号）作为**分发面的可替换性**处理，不升格为组织风险。

## 2. Stage 0 目标 / 非目标

目标：证明**一个**可售知识产品存在真实付费与正毛利。

非目标：
- 不建独立变现子组织
- 不新增 Agent
- 不做多产品线、不做投放规模化

## 4. 平台约束与 Stage 0 承载方式

Paperclip 强制 **一 Agent 绑定一 Project**（`projects_lead_agent_uq` 唯一索引；跨项目指派返回 `bound to project ... cannot work on another project`）。因此一个"零新增 Agent 的独立变现项目"不可行——新项目必须有专属 lead 才能被指派工作。

Stage 0 采用**现有项目承载**，不新建项目、不新增 Agent：

| Issue | 承载项目 | Assignee |
|---|---|---|
| KB-MON-1 单位经济与可售产品定义 | 咨询指挥部 `8038e7dc` | 首席顾问 `e43edda7` |
| KB-MON-2 渠道与可售内容盘点 | 洞察站点 `131af019` | 站点负责人 `fe189863` |

初建的「知识变现（Stage 0 验证）」项目 `6c6f8dbb` 因无法被指派而已归档（`archived_at` 已设）。

验证通过后，再新建专职变现负责人（1 个 Agent）并升格为子组织；届时项目才有归属与团队。

## 4. 通过判据（Stage Gate，阈值待人类确认）

1. 真实付费用户 ≥ 10（或 ≥1 个企业付费合同）
2. 毛利率 > 30%
3. 退款率 < 10%
4. 获客成本 < 客单价 × 30%
5. 履约可重复：同一产品至少完成 2 个完整交付周期

任一不满足 → 回到产品/定价，不加组织。

## 5. 已知系统缺口

**Paperclip 只有成本账（`cost_events` / budgets），没有收入/订单/权益台账。** "自己养活自己"需要收入侧数据：

- 短期：用 issue + 文档记录订单与毛利（Stage 0 可接受）
- 中期：`revenue` 插件（订单、退款、权益、毛利）
- 合规：微信支付资质、小程序知识付费类目、发票与税务

## 6. 反渠道化纪律

- 公众号与小程序共用一个渠道 runbook，不设两个负责人。
- 所有变现动作必须能回答"单位经济如何变化"。
- 不因单次爆款就扩组织；扩组织前必须满足第 4 节全部判据。
